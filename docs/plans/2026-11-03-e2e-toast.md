# 波次方案：toast 禁则修正 + Playwright E2E 首批（待审）

权威来源：本文 + [AGENTS.md](../../AGENTS.md) + [design.md](../design.md) + 代码。
背景：`docs/design.md` 禁则实例「toast 彩色左条」待修；`剩余清单.md` 手测项长期挂账，需逐步自动化。

## 技术选型（关键决策）

**Playwright 打纯浏览器，不引 tauri-driver。** `bindings/core.ts` 的 `resolveNativeInvoke()`
认 `window.__TAURI_INTERNALS__.invoke`——用 Playwright `addInitScript` 在业务代码执行前注入
fixture 路由（cmd → 夹具数据），应用即在 `vite dev` 下完整渲染，CI（ubuntu）稳定可跑。
真机 IPC 已由 Rust 集成测试守住，两层互补。`listen()` 走同一 invoke 接缝（`plugin:event|listen`），
fixture 返回空 unlisten 即可，App 无需改动。
